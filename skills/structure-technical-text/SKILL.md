# 技術文書を構造化する

## 目的

技術文書の位置づけ、重要な情報、情報間の関係を、短時間で把握できる箇条書きへ変換する。
原文の意味を保ちながら、情報密度と一覧性を高める。

## 原則

- 原文を全文読んでから変換する。
- 原文にない定義、根拠、具体例、評価、因果関係を加えない。
- 事実、条件、数値、固有名詞、専門用語、参照先、不確実性の強さを変えない。
- 原文の誤りや不足を推測で補わない。訂正や補足は、ユーザーから明示された場合だけ行う。
- 名詞句で意味が完結する項目は名詞句にする。
- 名詞句によって主語、対象、作用、比較、因果などの関係が曖昧になる場合は、関係を明記した短い文章にする。
- 補足、理由、具体例、条件は兄弟要素にせず、説明対象の子要素にする。
- 参考文献一覧への参照だけを示す文献引用マーカーは出力しない。
  - 例：`[5]`、`［5］`、`[3, 4]`、`［3-5］`
- 文献引用マーカーを削除しても、引用マーカーが付いていた主張や事実は残す。
- 出力では固定ラベル「この文章について」を除き、「この」「その」「それ」「これ」「こうした」「こういった」「これら」「それら」などの指示語を使わない。
- 変換後の箇条書きだけを出力し、前置き、感想、変換方針の説明を付けない。

## 手順

### 1. 文章の位置づけを特定する

- 文章が文書全体または議論の流れで果たす役割を特定する。
- 「この文章について」の子要素に、導入、比較、具体化、転換、結論などの位置づけを書く。
- 文章全体の具体的な結論や要約を「この文章について」へ書かない。
- 前後の文脈がない場合は、文章内部における議論の進み方を位置づけとして表す。

### 2. 意味の単位に分ける

- 一つの文に複数の情報があれば、意味の単位ごとに分ける。
- 複数の文が同じ内容を言い換えていれば、一つにまとめる。
- 因果、対比、列挙、条件、時間順序を識別し、関係を壊さない。

### 3. 論理的役割を判定する

各意味単位が読者に対して果たす論理的役割を、構造を決めるための内部基準として判定する。
論理的役割を固定の出力見出しとして使う必要はない。

- 前提：議論の開始に必要な背景、状況、既知の事実
- 定義：対象となる用語や概念の意味
- 問題提起：解くべき疑問、課題、対立
- 説明：仕組み、分類、手順、構成
- 補強：根拠、具体例、データ
- 比較：複数の対象の共通点や相違点
- 限定：条件、制約、例外、留保、適用範囲
- 転換：別の論点や見方への移行
- 帰結：前段から導かれる判断や含意

### 4. 内容固有のブロックにまとめる

- 最上位には「本文構造」を置かない。
- 「この文章について」の後に、原文の内容を表す具体的で短いラベルを並べる。
- 「説明」「補強」などの抽象的な役割名より、「実装例」「既存技術との比較」「選択条件」など、対象と関係が分かるラベルを優先する。
- ラベルだけで対象との関係が分からない場合は、対象をラベルへ含める。
  - 悪い例：`オープンソースのデータシステムへの普及`
  - 良い例：`実装例`
- 同じ対象に属する定義、特徴、実装例、条件などは、対象を表す親要素の配下にまとめる。

### 5. 情報価値の低い要素を削る

次の要素は、削っても論旨や理解に影響しない場合に限って削る。

- 同じ主張の言い換えや反復
- 本筋を進めない著者の感想や語りかけ
- 書籍や節の趣旨から外れる余談
- 読者にとって自明で、後続内容の理解に使われない説明
- 具体的な事実、関係、判断を含まない要素
- 内容を伴わない接続、強調、評価
- 参考文献、引用文献、Bibliography、Referencesなどの書誌情報一覧
- 本文中で参考文献一覧を指すだけの文献引用マーカー

次の情報は削らない。

- 主張の成立条件
- 因果関係を支える説明
- 反論、例外、制約、留保
- 比較によって示される相違
- 主張を支える具体例や事実
- 後続内容への実質的な転換や接続
- 本文の意味を補う脚注や注釈

文献引用マーカーと、脚注番号、章節番号、コード中の添字を区別する。
参考文献一覧への参照だと判断できない番号表現は削除しない。

### 6. 箇条書きへ変換する

- 名詞句で意味と関係が完結する項目は、句点を伴う文章にしない。
- 関係を明確にするために必要な場合だけ、短い文章を使う。
- 一つの項目には一つの情報を書く。
- 親項目に対する説明、理由、根拠、具体例、条件、結果を子項目に置く。
- 親子関係を表せる内容は並列にせず、ネストを増やす。
- 並列関係は同じ深さにそろえる。
- 見出しだけの空項目を作らない。

### 7. 重要箇所を強調する

- 文章の理解を左右する主張、判断基準、重要語だけを太字にする。
- 箇条書き要素の総数に対し、太字を含む要素の割合を10分の1未満にする。
- 一つの要素全体ではなく、重要な語句だけを太字にする。
- コード、数値、固有名詞を装飾目的で太字にしない。

### 8. 変換結果を点検する

- 「この文章について」が要約ではなく文章の位置づけを示しているか。
- 「主張概要」と「本文構造」が残っていないか。
- 各ラベルだけを読んでも、対象と情報の関係が分かるか。
- 名詞句への変換によって、主語、対象、作用、比較、因果が欠落していないか。
- 補足、理由、具体例、条件が説明対象の子要素になっているか。
- 情報価値の低い要素が残っていないか。
- 原文にない内容や因果関係を作っていないか。
- 実質的な情報を削っていないか。
- 禁止した指示語が残っていないか。
- 参考文献一覧や文献引用マーカーが残っていないか。
- 脚注番号、章節番号、コード中の添字を誤って削除していないか。
- 太字を含む要素が全要素の10分の1未満か。

## 出力形式

次の骨格を使う。
原文に存在するブロックだけを出力し、固定的な役割見出しを埋めるための空要素を作らない。

```markdown
- この文章について
  - {文書全体または議論の流れにおける位置づけ}
- {対象や関係が分かる内容固有のラベル}
  - {名詞句で完結する情報}
  - {説明対象}
    - {補足、理由、具体例、条件、または結果}
- {別の対象や関係が分かる内容固有のラベル}
  - {関係を省略できない場合の短い文章}
```

## 出力例

### 入力

Rubyでは、メソッド呼び出しに渡すブロックを、作成時の実行環境ごと後から呼び出せるオブジェクトとして扱えます。該当するオブジェクトがProcです。Procは呼び出し可能な無名の処理として利用でき、作成場所で参照できたローカル変数も保持します。Procオブジェクトを作る主な方法には、`Proc.new`、`Kernel#proc`、`Kernel#lambda`、`->`記法があります。`Proc.new`と`Kernel#proc`は非lambdaのProcを作り、`Kernel#lambda`と`->`記法はlambdaとして振る舞うProcを作ります。`&block`のようなブロック引数で受け取ったブロックも、`Proc.new`と同じ性質を持つ非lambdaのProcになります。

生成方法が異なっても、生成結果はすべてProcクラスのインスタンスです。ただし、lambdaとして振る舞うProcと非lambdaのProcでは動作が異なります。lambdaはメソッドに近い規則を持ち、呼び出し時の引数の個数が定義と一致しなければ`ArgumentError`を発生させます。非lambdaのProcは引数を多重代入に近い規則で割り当てるため、足りない引数には`nil`を割り当て、余分な引数は無視します。

制御フローにも差があります。lambda内の`return`はlambdaの呼び出しだけを終了させます。非lambdaのProc内の`return`は、Procが作られたメソッドから処理を戻します。Procを作ったメソッドがすでに終了している状態で、非lambdaのProcから`return`または`break`を実行すると、`LocalJumpError`が発生します。lambdaではジャンプがlambda内で完結するため、同じ状態でも`LocalJumpError`は発生しません。Procクラスであるという共通点だけでは代替可能とは判断できず、引数と制御フローの違いを踏まえて生成方法を選ぶ必要があります。

### 出力

```markdown
- この文章について
  - Procの定義と生成方法を導入し、lambdaと非lambdaの挙動差から選択基準を示す比較解説
- Proc
  - 定義
    - ブロックを作成時の実行環境ごと保持し、後から呼び出せるオブジェクト
  - 特徴
    - 呼び出し可能な無名の処理
    - 作成場所のローカル変数の保持
  - 生成方法
    - 非lambdaのProcを生成
      - `Proc.new`
      - `Kernel#proc`
      - ブロック引数
    - lambdaとして振る舞うProcを生成
      - `Kernel#lambda`
      - `->`記法
- lambdaと非lambdaのProcの比較
  - 共通点
    - 生成結果はProcクラスのインスタンス
  - 引数の扱い
    - lambda
      - **定義と異なる引数の個数に対する`ArgumentError`**
    - 非lambdaのProc
      - 多重代入に近い引数割り当て
        - 不足する引数への`nil`の割り当て
        - 余分な引数の無視
  - `return`の扱い
    - lambda
      - lambdaの呼び出しだけを終了
    - 非lambdaのProc
      - Procを作成したメソッドから処理を戻す。
      - 作成元メソッドの終了後に`return`または`break`を実行すると、`LocalJumpError`が発生する。
    - 作成元メソッドの終了後におけるlambda
      - ジャンプがlambda内で完結するため、`LocalJumpError`は発生しない。
- 生成方法の選択基準
  - **引数と制御フローの違い**
```
