# 技術文書を構造化する

## 原則

- 指定された範囲の全文を読んでから変換する。
- 原文にない定義、根拠、評価、因果、具体例を加えず、事実、条件、専門用語、参照先、不確実性を変えない。
- 文章全体の位置づけを先に決め、その役割に出力の粒度を合わせる。
- 最上位の各項目を、`導入`、`前提`、`問題`などの短い論理的役割の見出しにする。
- 中心命題と、理解に不可欠な最小限の因果だけを残す。
- 初見の読者が「何の話か」「何と何の関係か」「なぜ重要か」を追える表現にする。
- 重複、余談、自明な説明は削り、主張の条件、因果、反論、例外、重要な比較は残す。
- 参考文献一覧と、一覧を指すだけの`[5]`、`［3-5］`などの文献引用マーカーを削る。
- 変換後の箇条書きだけを出力する。

## 手順

### 1. 範囲と文脈を確認する

- 本文が提示された場合は、提示された本文全体を変換範囲とする。
- 節名や章節番号で指定された場合は、該当見出しから同じ階層以上の次の見出しの直前までを読む。
- 検索結果や節の冒頭だけで、未確認部分を推測しない。
- 全文を取得できない場合は、完成した変換結果を作らず、不足範囲の提示を依頼する。
- 文書全体を利用できる場合は目次上の階層と前後を確認し、文脈は位置づけの判断だけに使う。

### 2. 文章全体の位置づけを決める

- 次のうち、文章全体の主な役割を一つ選ぶ。
  - 導入または概要：視点、論点、問題、後続の進行を提示
  - 詳細解説：定義、仕組み、理由、条件、帰結を説明
  - 比較：比較対象、比較軸、相違、選択への含意を提示
  - 具体化：前段の説明を事例や実装で補強
  - 結論または接続：判断を示すか、次の論点へ移行
- 既出事項を振り返り、問題意識を示し、後続の話題を予告する文章は、定義や比較を含んでいても導入または概要と判定する。
- 導入文では視点、論点、問題、進行を中心にし、定義、比較、既出事項、具体例は必要な一項目へまとめるか省く。
- 詳細解説では、中心的な主張と、理解に不可欠な仕組み、理由、条件、帰結だけを残す。
- 具体例、補足的な言い換え、名称の提案、歴史上の細部は、結論を左右しない限り省く。
- 出力前に、文章の本質を一文で表し、その一文へ至る最短の論理だけを選ぶ。

### 3. 論理的役割へ分ける

- 原文を意味の単位へ分け、因果、対比、条件、時間順序を保ち、同じ内容の言い換えはまとめる。
- 各意味単位を次の役割へ分類する。
  - `導入`：文章の位置づけ、話題、目的、見通し
  - `前提`：議論に必要な背景、既知の事実、定義
  - `問題`：解くべき疑問、課題、対立
  - `主張`：文章が示す結論、判断、中心的な見方
  - `原因`または`仕組み`：主張が成り立つ理由や過程
  - `比較`：対象間の共通点、相違、選択への含意
  - `対策`：問題への対応方法
  - `具体例`：主張の理解に不可欠な例
  - `限定`：条件、制約、例外、留保、反論
  - `結論`：帰結、意義、一般化
  - `接続`：前段との関係、次に扱う論点
- 最上位の見出しにはこの役割名を使い、直下に内容を直接書く。
- `問題`にはタイトルや結論が答える中心的な疑問を優先し、`結論`と直接対応させる。
- 下位節や比較対象は原則一項目へ要約し、条件や例外が結論を変える場合だけ子要素を加える。
- 原文の順序にかかわらず、該当する見出しを`導入`、`前提`、`問題`、`主張`、`原因`、`仕組み`、`比較`、`対策`、`具体例`、`限定`、`結論`、`接続`の順に並べる。

### 4. 導入と情報量を整える

- `導入`には、確認できた文脈に応じて次を置く。
  - `これまで：{直前までに確立された議論}`
  - `本節：{文章全体の役割と扱う論点}`
- 前後の文脈がない場合は、文章内部での位置づけだけを書く。
- 文章全体が導入なら、独立見出しは原則として`導入`、`前提`、`問題`、`接続`だけにする。
- 導入中の定義、比較、主張は、必要なら`前提`か`問題`へ統合し、詳細解説の独立見出しにしない。
- 導入の後続項目の列挙は、個々の説明ではなく進行を示す一項目へまとめる。
- 比較では両方の対象と比較軸を明記する。
- 指定がなければ、最上位見出しは最大6個、情報を持つ末端項目は最大12個とし、短い文章を水増ししない。
- 一つの役割には中心的な内容を1〜3項目だけ置く。
- 製品名、人名、年、数値、事例は、中心命題の理解に不可欠な場合だけ残す。
- 初出の略語や別名は既知として使わず、関係が分かる形で導入するか、不要なら省く。
- 同種の列挙や複数の事例は上位概念へまとめ、違い自体が結論を左右するときだけ分ける。
- 位置づけ、中心命題、因果、条件、帰結を優先し、比較対象や因果を途中で切らない。
- 引用マーカーが付いていた主張は残し、脚注番号、章節番号、コード中の添字を削除・一般化しない。
- 固定ラベル`これまで`を除き、参照先が曖昧な指示語を使わない。

## 出力形式

次の形を基本とし、原文に該当する見出しだけを出力する。

```markdown
- 導入
  - これまで：{直前までに確立された議論}
  - 本節：{文章全体の役割と扱う論点}
- 前提
  - {議論に必要な情報}
- 問題
  - {解くべき疑問や課題}
- {主張、原因、仕組み、比較、対策、具体例、限定、結論、接続のうち該当する役割}
  - {内容を直接表す項目}
    - {必要な場合だけ、仕組み、理由、具体例、条件、帰結など}
```

## 点検

- 指定範囲の全文と、確認可能な前後の文脈を読んだか。
- 最上位が論理的役割の見出しになっているか。
- 文章全体の位置づけと粒度が一致し、導入文を詳細解説のように分解していないか。
- 中心命題へ至る最短の論理だけになり、末端項目が12個以内に収まっているか。
- 原文にない内容を補わず、実質的な情報も削っていないか。
- 比較対象、指示対象、因果、条件が読み取れるか。
- ユーザーが指定した行数、項目数、詳しさに収まっているか。
